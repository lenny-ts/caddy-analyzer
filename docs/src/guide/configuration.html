Configuration

How the tool itself is configured. For how to connect to each log source, see Log Sources.

Config file — where it lives

Two locations, first hit wins:

PathScope
./caddy-analyzer.jsonLocal (project)
~/.config/caddy-analyzer/config.jsonGlobal (XDG)

~/.config follows XDG_CONFIG_HOME if set, else os.UserConfigDir(). Dirs are created 0750, files 0600.

Schema

{
  "source": "docker://caddy",
  "namespace": "production",
  "blocklist": {
    "no_defaults": false,
    "custom_sources": [{ "name": "My List", "url": "https://example.com/list.txt" }],
    "remove_sources": ["tor-exit-nodes"]
  },
  "tuning": {
    "geo_cache_ttl": "24h",
    "geo_cache_size": 50000,
    "iptables_timeout": "10s"
  }
}

Manage it

caddy-analyze config                    # show active file + source
caddy-analyze config /var/log/caddy/access.log          # set local
caddy-analyze config docker://caddy --global            # set global
caddy-analyze config k8s://caddy-xxx -n production     # with namespace
caddy-analyze config reset              # remove local
caddy-analyze config reset --global     # remove global
caddy-analyze blocklist init            # persist blocklist flags to config
caddy-analyze whitelist --init          # persist never-block to /etc/caddy-analyzer/whitelist.txt

blocklist init writes current --no-default-blocklists / --blocklist-config / --blocklist-remove into the same file so guard picks them up without CLI flags.

Guard server-IP protection

--protect-self=true is a guard-only CLI flag, not a field in caddy-analyzer.json. Discovered interface/public egress addresses remain in memory. Guard loads the selected whitelist at startup and reloads it every 30 seconds without restarting; explicit --never-block entries remain in force. See reload validation and subnet-ban cleanup.

For an offline, proxy-only or fixed-IP deployment, put --protect-self=false in the guard service's startup arguments. This disables automatic server-IP discovery without disabling explicit never-block entries. Direct public discovery ignores http_proxy/https_proxy. See guard and discovery errors.

Tuning — precedence

Config file values are defaults; CLI flags override when explicitly set. The three tunables:

KeyConfig fieldCLI flagDefault
GeoIP cache TTLtuning.geo_cache_ttl--geo-cache-ttl 24h24h (0 = off, slow)
GeoIP cache sizetuning.geo_cache_size--geo-cache-size 5000050000
iptables timeouttuning.iptables_timeout--iptables-timeout 10s10s
 
# example: keep GeoIP results longer on a busy host
caddy-analyze --geo-cache-ttl 48h --geo-cache-size 100000 /var/log/caddy/access.log

Behavioral authentication abuse (opt-in)

Add this object to the active configuration. enabled activates detection; block separately enables per-IP brute-force/stuffing bans in guard. Aggregate spraying is always alert-only.

{
  "behavioral_detection": {
    "auth_abuse": {
      "enabled": true,
      "block": false,
      "endpoints": ["/login", "/api/login", "/wp-login.php"],
      "failure_statuses": [401, 403],
      "brute_force": {"failures": 10, "window": "1m"},
      "credential_stuffing": {"failures": 20, "unique_uas": 5, "window": "1m"},
      "password_spray": {"failures": 100, "unique_ips": 20, "window": "5m"}
    }
  }
}

Endpoints are exact case-sensitive decoded paths, separated by request host; query strings are ignored. Failure statuses must be 400–599. Omitted scenarios use the defaults shown; to disable one, set its failures to 0 and supply a valid window. Windows must be positive and at most 24h; failures are capped at 100,000; distinct-UA/IP thresholds must be between 2 and the corresponding failure threshold.

Use --detect in reports/tail/watch. These high-severity, confidence-7 signals indicate suspected abuse, not compromised accounts: usernames/passwords are not extracted. Stuffing uses UA diversity; spraying appears under aggregate in reports. Offline analysis uses log timestamps; guard uses receipt time and retains evidence across normal window resets. Each enabled scenario retains at most 100,000 failures (300,000 total); new evidence is dropped when full until older failures expire.

Guard's block: true path is independent of --detect-confidence and still honors allowlists, self-IP protection and dry-run. The old --auth-limit remains a separate 401/403 threshold across all paths; set it to 0 if only endpoint-scoped rules are wanted. Other guard rules remain active.
